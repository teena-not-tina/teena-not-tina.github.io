## 상황
소스 폴더가 컨테이너에 마운트된 개발 환경에서, 같은 `pytest`를 호스트와 컨테이너에서 번갈아 돌렸다. 두 종류의 실패를 겪었는데 **원인이 같았다.**
## 증상 1 — 테스트가 이유 없이 느리다
```javascript
socket.gaierror: [Errno 8] nodename nor servname provided
```
`.env`의 `POSTGRES_HOST`가 컨테이너 이름(`<프로젝트>-db`)이라 **Docker 네트워크 안에서만** 풀린다. 호스트에서 돌리면 DB fixture가 매번 DNS 재시도 백오프를 먹는다.
**진단 요령**: 테스트가 느릴 때 `ps aux`로 CPU를 본다. pytest가 CPU 상위에 없으면 계산 중이 아니라 **기다리는 중**이다. 기다림은 거의 항상 네트워크·I/O다.
## 증상 2 — 테스트가 시작조차 못 한다
```javascript
ImportPathMismatchError: ('modules.indexing.tests.conftest', ...)
collected 1442 items / 1 error
```
파이썬은 `__pycache__/*.pyc`에 소스의 **절대경로를 박아둔다.** 호스트에서 돌리면 `/Users/...`가, 컨테이너에서는 같은 파일이 `/project/...`가 된다. 마운트로 같은 파일을 공유하니 경로가 어긋나고, pytest는 "같은 모듈이 두 경로에 있다"며 **수집 단계에서 멈춘다.**
실패가 아니라 시작 실패라, 로그만 보면 코드가 망가진 것처럼 보인다.
```bash
find . -name __pycache__ -type d -exec rm -rf {} +
```
## 재사용 규칙
**한 곳에서만 돌린다.** 컨테이너 테스트를 쓸 거면 호스트 pytest를 섞지 않는다. 반대도 같다.
그리고 로그를 읽을 때 이걸 먼저 가른다.

같은 코드가 호스트에서 34 error, 컨테이너에서 1522 passed였다. **어디서 돌렸는지를 빼고 결과를 해석하면 틀린다.**
